# Design

## Precedence

The Figma file (`zbnAZgE9m0T1nf6HDTDFvw`, pages Fundamentos and Componentes, plus the PNGs in `docs/design/mockups`) is a **guide, not a rule set in stone**. It fixes the identity (palette and the role of each color, the three fonts, the tokens, the component vocabulary and the general composition of each screen), and that identity is kept. Inside it, the better pattern wins: when the mockup conflicts with a good practice from the design skills (`emil-design-eng`, `mobile-native`, `impeccable` audit/craft-floor, `review-animations`, `break-ui`) or with a pattern already established in this project (these rules and the existing components), follow the skill or the project pattern and record the deviation here. Examples already applied: errors as toasts instead of the inline alert, secondary text darkened to WCAG AA, 44 px touch targets.

Order when deciding: project patterns (these rules, existing code) > design skills > mockup details. The identity above never changes because of a skill (DM Mono stays even if a skill dislikes monospace).

## Login deviations

- `/login` follows mockup 01 with two changes: the user is identified by CPF (mask, `autocomplete="username"`, numeric keyboard) instead of the e-mail, and there is no "Esqueci minha senha" link, since no recovery flow exists. The dark panel has no role list: below the dot row, desktop only, a "Primeiro acesso" block (mono eyebrow + `body-s` secondary text) tells new users to register the company or use the e-mail invite; on mobile the panel matches the 390 px mockup.
- The tab icon is `src/app/icon.svg` and `src/app/apple-icon.png` (the `Logo` bars on a rounded Shadow Grey square; full square for the apple icon), with no `favicon.ico`. These icon files are the only place with hex literals, since they cannot read CSS tokens; the bars are 4 units wide with a 2-unit gap in the 32-unit `icon.svg`, so they stay 2 px wide in a 16 px tab.
- Secondary text on the dark panel uses `text-text-inverse-secondary` (`--color-text-inverse-secondary`, alias of mist, 9:1 on shadow grey) instead of an opacity of the inverse text; `--container-card` (460 px) is the login card width.

## Organizers screen deviations

- `/organizadores` (admin, inside `BackofficeLayout`) follows mockups 08 and 08b for the list and the detail, which now carry the actions (see below). Deviations: no counts in the tabs or in the header eyebrow, since no endpoint counts by status and the eyebrow is only "Administração"; no coral counter in the navigation (same reason); no `ORG-xxxx` code (the API has none; the detail header shows "Criado em <date> às <time>" and "Última atualização <date> às <time>" in DM Mono instead of "Cadastro ORG-xxxx · Enviado em"); no owner name in the row (the list endpoint does not carry it, and loading it per row would be one request per company), so the row shows razão social, CNPJ, "Criado em" and the badge; no events/team line in the approved detail (data not available); the detail shows the contact with e-mail and the phones, one per line, because a company can have several; nothing is pre-selected on any width, the desktop right column shows an `EmptyState` ("Selecione uma empresa para ver os dados.") only while the list has items and nothing is selected (first load, empty list, search without result and list error leave the column empty, grid unchanged), the selection survives crossing 1024 px (only the detail position changes: beside the list on desktop, below the row on mobile) and clicking the selected row again closes the detail (toggle, `aria-expanded` on both widths, no `aria-current`); reloading the list (tab or search) clears the selection only when the selected company is not in the new list.
- The list is paged by 30 with a "Carregar mais" outline button (shown only when the last page came full) instead of the mockup's fixed list. The search is debounced (300 ms) and sends one field to the API: text made only of digits, `.`, `/` or `-` goes as `document_number` (digits only, exact CNPJ, so a partial CNPJ finds nothing until it is complete), anything else goes as `name` (prefix of the razão social); the field is a `SearchField` (`type="search"`, 16 px, `sr-only` label "Buscar por razão social ou CNPJ") instead of a visible label.
- Two-column layout (list + detail panel, nothing preselected) from `lg` (1024 px) and not from `md`: next to the 264 px sidebar the content is only about 400 px wide at 768 px, too narrow for two columns. At `lg` the columns are equal (`lg:grid-cols-2`); from `xl` the detail column is fixed at `--column-detail` (496 px) and the list takes the rest (`xl:grid-cols-[minmax(0,1fr)_var(--column-detail)]`), which gives the mockup's 560 + 496 at 1440 px and keeps the row on one line (name and CNPJ on the left, "Criado em", badge and arrow on the right). Below `lg` the tabs become the native `StatusFilter` select ("Situação: Pendentes"), the detail opens inline below the tapped row (`aria-expanded`) and tapping the row again closes it; the row is a button with `aria-expanded` on both widths (never `aria-current` or `aria-pressed`: clicking the selected row closes it), and `aria-controls` points at the detail ids while it is selected. The selected row uses a 2 px sky aqua border (border-2 always, so the row does not shift) instead of the mockup's 1 px lighter border plus outline. Sky aqua is 2.1:1 on white and stays as the identity color of the selection, so the selection never depends on it alone: the desktop arrow goes from `text-text-secondary` to an inverted square (`bg-bg-inverse text-text-inverse`), and on mobile the open inline detail is the signal. The row hover is `hover:bg-fill-subtle`. When a row is opened, its list item (row plus inline detail) is scrolled into view with `block: 'nearest'` and `scroll-my-md` once the detail finishes loading (success or error, so the measured height already has the company and owner sections), never on close nor when the list reloads keeping the selection: on desktop the inline detail is `display: none`, so only the row is brought into view, and on mobile the open inline detail comes along instead of staying off screen; smooth only without `prefers-reduced-motion`. Desktop × mobile is pure CSS (`lg:`): `Tabs` and `StatusFilter` are both rendered (`hidden lg:flex` / `lg:hidden`), the detail is mounted twice (side column `hidden lg:block`, inline below the row `lg:hidden`) each with its own `useId` id, the row's `aria-controls` lists both ids separated by a space, and the arrow is `hidden lg:flex`; the list wrapper is always `role="tabpanel"` labelled by the active tab.
- `OrganizerDetail` is the same on both widths and knows nothing about where it is placed: the stickiness and the scroll belong to the side column of `PageView`, which stretches to the height of the list (`lg:self-stretch`, since the grid is `lg:items-start` and a sticky element only moves inside its parent) and wraps the side instance in a container `sticky top-2xl`, `max-h` of `100dvh` minus twice `--spacing-2xl`, `overflow-y-auto` and `tabIndex={0}` (keyboard users can scroll it, with the global `ink` focus outline), so it stays beside a long list; the inline instance has no wrapper, no inner scroll and is not focusable. Every data value in the detail (CNPJ, contact, CPF, e-mail) is `mono-m`; names are `label-m`.
- Reloading (tab or search change, retry with items): the old items stay with `aria-busy="true"`, `inert` and reduced opacity, with no new animation, until the response arrives; selection and detail only change when the new list is in. The `sr-only` "Carregando" is only for the first load (no items yet). A search equal to the applied one (same `name`/`document_number` filters) does not reload; "Carregar mais", retry and the empty message use the applied search, not the typed one. A page appended to the list drops items already present; "Carregar mais" shows when the last page came full, so a total that is an exact multiple of 30 shows one extra button that answers an empty page (accepted).
- Results are announced by an always-mounted `role="status"` `sr-only` region in `PageView`: "N empresas", "Nenhuma empresa encontrada" and "Mais N empresas carregadas".
- The row's right group wraps (`flex-wrap min-w-0`) so it never overflows between 1024 and 1100 px. Tabs keep automatic activation by arrow keys, because stale requests are discarded.
- The detail opens without animation: it is a frequent action and the content changes place. Loading, empty, search-without-result and error states reuse `role="status"` with `sr-only` "Carregando", `EmptyState` and the error toast; the list error block and the detail error carry "Tentar de novo".

## Organizer actions deviations

- The detail ends with `OrganizerActions` (route component), shown only once the company data loaded. `PENDING`: a `Select` "Motivo (obrigatório para reprovar)" with the reasons of `GET /internal/organization_rejection_reasons` (fetched once, on the first open of a pending company, and not again while the list stays empty; while loading it is disabled with "Carregando motivos" and Reprovar is disabled too; on failure a toast plus a short message and "Tentar de novo" replace it, and an empty list (no error) shows "Nenhum motivo de reprovação disponível." with the same retry; in both cases Reprovar is disabled), "Aprovar" (`primary`, check) and "Reprovar" (`outline`, X) side by side when the detail is at least 22 rem wide and stacked full width below it (container query: `OrganizerDetail` is an `@container` and the button groups use `@min-[22rem]:flex-row`, so the layout follows the width of the detail and not the viewport; between 1024 and 1279 px the side column has about 270 px and the pairs stack), and the lemon-lime footnote. `APPROVED`: "Remover empresa" (`outline`). `REJECTED` and `DELETED`: no actions. The state lives in `page.tsx` (`actions`, `rejectionReasons`) because the detail is mounted twice, and `actions` resets whenever the selection changes or closes, except `pendingAction` and `pendingOrganizationKey`: while a request is in flight every button (of any company) stays disabled, closing and reopening the detail does not enable them again, and only the buttons of the company that owns the request show the loading state. A synchronous `actionInFlightRef` blocks a second submission before React re-renders. The reload after a success uses the status and the applied search at the moment of the response (`statusRef`, `appliedSearchRef`), not the ones captured at the click.
- The organization status `ERROR` does not exist in the app: it has no tab, badge or alert, and the analysis is done outside the screens. When the approval answers 422 `ORG00005`, the toast shows the API message, the detail closes and the tab reloads, because the company left the pending list. An owner in that status sees the awaiting approval state in `/situacao`. The company block of the detail also shows "Tipo da empresa", "Faturamento mensal" and "Endereço" (logradouro and number, complement, neighborhood, CEP with mask), all with `break-words`; the mockups 08 and 08b do not have them.
- Deviations from 08 and 08b: the reason is chosen in a `Select` fed by the reasons table, not free text; the removal has no reason field; the footnote promises no e-mail ("mostra o motivo na tela de situação"); the alert text does not mention members, events or the audit ("A dona deixa de entrar no backoffice. A empresa fica na aba Removidos."); the "Remover empresa" button comes before the confirmation block, which the mockup shows already open; Aprovar has no confirmation; Reprovar without a reason shows the local error "Selecione o motivo para reprovar." on the `Select` and moves the focus to it (the button is never disabled for a missing reason; it is only disabled while the reasons load, when the list is empty or failed, or while an action runs). The error `<p>` of `Select` and `Field` is `role="alert"`, so it is announced even when the focus moves in the same render that creates it. The footnote keeps the mockup's lemon-lime left border (2 px) even though `craft-floor` discourages colored side borders above 1 px: it is the identity of that note and carries no state.
- Focus: opening the removal confirmation focuses the alert (`tabIndex={-1}`, `preventScroll`) and scrolls the whole block (alert plus Cancelar/Confirmar) into view with `block: 'nearest'` and `scroll-my-md`, smooth only without `prefers-reduced-motion`, so the buttons never stay below the fold of the side column; Cancelar returns it to "Remover empresa". While an action runs, the triggered button is `loading` (`loadingLabel` "Aprovando", "Reprovando" or "Removendo") and the others are `disabled`. Success: success toast, the focus goes to the tab panel (`tabIndex={-1}`, labelled by the active tab, so the position stays inside the list after the detail unmounts), the selection closes and the current tab reloads; a success for a company that is no longer selected only reloads. Error: the API message toast and the detail stays open; the pending state is released whichever company is selected, because it belongs to the request and not to the selection.

## Colors (light theme)

- Platinum (`bg-page`, `text-inverse`): page background.
- Shadow grey (`text-primary`, `bg-inverse`, `ink`): text, ticket stubs and inverted surfaces.
- Vibrant coral (`action-primary`, `feedback-danger`): the main action and urgency/error. **One coral action per screen.**
- Lemon lime (`accent-live`): real time only, and only as the **background** of dark text, never as text color.
- Sky aqua (`accent-selected`): selection only.
- White (`bg-surface`) for cards and fields; mist (`seat-occupied`) for occupied seats.
- Secondary text uses `text-secondary` (`--color-text-secondary`, solid `#545a66`, 6.1:1 on platinum and 6.9:1 on white): section numerals, eyebrow, hints, terms, pending step and placeholder. Text is never lowered by opacity (`text-text-primary/60` is forbidden); a deliberate deviation from the mockup, whose greys are lighter than WCAG AA allows.
- Borders and fills use `border-subtle`, `border-strong` and `fill-subtle` (alpha of shadow grey); `fill-muted` (solid `#545a66`) is the mid grey of graded fills such as the progress bars of the current step. Text tokens are never used as fills and background tokens never as borders.

## Tokens

- Tokens live only in `src/app/globals.css` (`@theme`): `--palette-*`, semantic `--color-*`, `--spacing-2xs..3xl` (4, 8, 12, 16, 24, 32, 48, 64), `--radius-sm|md|full` (2, 6, 999).
- Use them as classes: `bg-bg-page`, `text-text-primary`, `border-border-strong`, `p-md`, `gap-xs`, `rounded-sm`. Never a loose hex, never an arbitrary value when a token exists (an arbitrary `var(--token)` is fine).
- Caution: `--spacing-*` also feeds `max-w-*`/`w-*` named sizes, so `max-w-sm`, `max-w-xl`, `max-w-3xl` resolve to 12, 32 and 64 px. Layout widths are tokens too: `--container-page` (1440 px) and `--column-intro` (340 px), used as `max-w-(--container-page)`; add a new token instead of a loose width.
- Arbitrary values are accepted only for measures taken from the Figma that have no token (icon and logo sizes such as `size-7`, `size-8`, the logo bars and the toast badge `text-base`); spacing and padding always use tokens.
- `--header-height` (56 px mobile, 76 px from `md`) is the public header height.
- Radius is 2 px (`rounded-sm`) on buttons, fields and cards.

## Typography

- Big Shoulders Display Black, uppercase: `display-xl|l|m|s` (104, 72, 56, 40).
- Familjen Grotesk: `title-l|m|s` (SemiBold), `body-l|m|s` (Regular), `label-m` (Medium), `button-m|s` (SemiBold).
- DM Mono: `mono-l|m` (Medium), `mono-s` (Regular), `mono-eyebrow` (Medium, uppercase, 1.2 px tracking).
- These are Tailwind utilities declared in `globals.css` (`@utility`); use them instead of `text-*`/`font-*` combinations.
- `@utility` blocks in `globals.css` never use nested selectors (`&[data-open='true']`, `&:hover`): SonarQube reads them as CSS without a scoping root (`css:S8776`) and fails the quality gate. A state gets its own utility applied with a Tailwind variant (e.g. `motion-menu-panel` plus `data-[open=true]:motion-menu-panel-open`).
- Data (documents, dates, amounts, codes) is always in DM Mono.

## Components and screens

- Notifications are toasts (Sonner, one `<Toaster>` in the root layout, `toast.error`/`toast.success` from `src/lib/toast.tsx`, rendered with the `Toast` component): error in coral with the "!" badge, success in shadow grey with a lemon-lime check; top right on desktop (16 px from the top of the viewport, aligned with the page gutter) and full width at the top on mobile (8 px); the header is not fixed, so the toast never reserves its height; error stays 6 s, success 4 s, both closable. This replaces the inline error alert of the mockups (a deliberate deviation for the whole project).
- Every screen is built with the base components of `src/components/` (`Logo`, `Button`, `Field`, `Toast`, `PublicHeader`, ...) and has a 390 px version besides the 1440 px one.
- New components come from the Figma page "Componentes" and keep the variant names (Button: primary, dark, outline, highlight, outline-inverse × m, s; Field: default, error, empty × text, numeric). A component is only created when a screen uses it.
- Status and feedback components: `StatusBadge` ("Selo de situação", `status`: pending, approved, rejected, deleted; light surface by default, `inverse` for dark surfaces such as the `/situacao` hero; it is a `span`, so it can live inside a button), `TimelineStep` ("Etapa da linha do tempo", `state`: done, current, rejected, pending) and `EmptyState` (optional `title`, rendered as `h2` or the `titleAs` level, and `action` below the message; the message-only form is the compact centered box, the form with title/action is the left-aligned card on `bg-surface`, on purpose). The other states are added when a screen uses them. `Tabs` ("Aba": `role="tablist"`, `aria-selected`, roving `tabIndex`, arrows/Home/End select, coral underline on the active tab, generic over the value type), `SearchField` ("Campo" variant with a magnifier, `type="search"`, accessible `aria-label`) and `OrganizerRow` ("Linha de organizador": device × selected, `aria-expanded` on both widths, `aria-controls` to the detail) are base components of the organizers screen. `Select` (Figma "Campo" as a native `<select>`: same label, `hint`, `error`, border and focus as `Field`, arrow like `StatusFilter`, empty option with the placeholder, 44 px minimum height, 16 px text, `ref` as a prop; disabled dims the whole container, label and arrow included, with `has-[:disabled]:opacity-50`) is a base component of the organizers screen. `Alert` (Figma "Alerta", prop `type`; only `danger` for now: coral surface, dark round "!" badge, `title-s` title as `h3` by default or the `titleAs` level, `body-s` text, focusable with `tabIndex={-1}` so a confirmation can take the focus) is used by the rejection reason of `/situacao` (`titleAs="h2"`) and the removal confirmation of `/organizadores`; it is a `div role="group"` (not a `section`, which a label would turn into a region landmark) labelled by the title and described by the text (`aria-labelledby`, `aria-describedby`), so focusing it reads both; it is static, and the removal animates a wrapper that holds the alert and the Cancelar/Confirmar buttons together with `animate-alert-in`, so the focused alert does not move alone.
- Accessibility: touch targets of at least 44 px (invisible padding, never a visual change); state is never conveyed by color alone (`sr-only` text); a loading button keeps its label in the DOM and uses `aria-disabled`, so focus is not lost; the password toggle is a plain button whose visible text is its name ("mostrar"/"ocultar", `aria-controls` on the field), never `aria-label` different from the visible text (WCAG 2.5.3); a `Button` of size `s` keeps `min-h-11`; the `sr-only` text of a loading `Button` is `loadingLabel` (default "Enviando"; "Carregando" on a load-more button), so a screen reader never announces a submission that is not one. A horizontally scrolling strip (`overflow-x-auto`) clips the focus outline, so it gets token padding on the clipped sides (`pt-xs`) to give the outline room. A screen with nothing to show while hydrating or redirecting renders a `role="status"` block with `sr-only` "Carregando" and keeps the page background.
- Mobile: inputs at 16 px or more (no iOS zoom), `100dvh` instead of `100vh`, hover only under `(hover: hover)` (Tailwind's `hover:` already does it), `autocomplete` on every field, visible keyboard focus with the `ink` outline.

## Motion (everything off under `prefers-reduced-motion`)

| Element                                | Trigger         | Properties                          | Duration       | Easing                                   |
| -------------------------------------- | --------------- | ----------------------------------- | -------------- | ---------------------------------------- |
| Button                                 | press           | `transform: scale(0.97)`            | 120 ms         | ease-out                                 |
| Button, link, field                    | hover/focus     | background/border color             | 150 ms         | ease                                     |
| Toast                                  | enters / leaves | Sonner default (transform, opacity) | Sonner default | Sonner default (respects reduced motion) |
| Field error                            | appears         | opacity 0→1                         | 150 ms         | ease-out                                 |
| Button spinner                         | submitting      | rotation                            | 700 ms/turn    | linear                                   |
| Toast close button                     | hover           | background color                    | 150 ms         | ease                                     |
| Mobile menu panel                      | opens           | opacity 0→1, `translateY(-4px→0)`   | 150 ms         | ease-out                                 |
| Mobile menu panel                      | closes          | opacity 1→0                         | 100 ms         | ease-out                                 |
| Nav item                               | hover/focus     | background color                    | 150 ms         | ease                                     |
| Tab                                    | hover/active    | text and underline color            | 150 ms         | ease                                     |
| Organizer row                          | hover/selected  | border and background color         | 150 ms         | ease                                     |
| Select                                 | focus/error     | border color (`motion-color`)       | 150 ms         | ease                                     |
| Removal confirmation (alert + buttons) | opens           | opacity 0→1, `translateY(4px→0)`    | 180 ms         | `cubic-bezier(0.23, 1, 0.32, 1)`         |

Under `prefers-reduced-motion` the spinner is the only exception: it keeps rotating slowly (1.4 s/turn, linear) because it communicates the submitting state. Page changes, the "mostrar" password toggle and the side steps are not animated. Never `transition: all`; never `ease-in`.
